# Контракт регистрации и профиля

Базовый адрес: `/api/v1`. Источники: [передача бэкенду](https://github.com/Smart-aqmola/aqmola-portal/blob/dev/docs/backend-handoff.md), [контракт фронта](https://github.com/Smart-aqmola/aqmola-portal/blob/dev/docs/api-contract.md), проверки `account/domain/profile.ts`, `phone.ts`, `iin.ts` в ветке `dev`.
Это описание реализованной части API, а не замена общего контракта проекта.

## Согласованные решения

23 октября 2026 года пользователь согласовал таймаут бездействия 30 минут и коды ошибок регистрации и входа ниже.
Абсолютный срок сессии остаётся 7 дней; активность продлевает только таймаут бездействия. Проверка происходит на каждом защищённом запросе и сохраняется в PostgreSQL.
Значение задаётся `SESSION_IDLE_MINUTES` (от 1 до 1440). Старые сессии при миграции получают `lastSeenAt` из `createdAt`, чтобы не возобновлять давно неиспользуемые сессии.

## Запрос кода и регистрация

`POST /auth/otp/request`:

```json
{ "phone": "+77001234567", "purpose": "register" }
```

Ответ 202: `challengeId` (UUID), `expiresAt` (UTC ISO 8601), `resendAfterSeconds`.
`purpose` принимает `register` или `login`. Номер нормализуется как на фронте: `+7…`, `8 (…) …` и 10 цифр без кода страны.
Код остаётся случайным и одноразовым; значение `123456` не является специальным.

`POST /auth/register`: `challengeId`, `code`, `iin`, `firstName`, `lastName`, `consent: true`; необязательные `middleName`, `email`, `phone`.
Телефон берётся из запроса кода. Если он также передан в форме, сервер требует совпадения после нормализации.
ФИО: до 60 символов, буквы, пробелы, апострофы и дефисы согласно проверке фронта. Email: до 100 символов. Пустые необязательные строки не сохраняются.
ИИН: 12 цифр и возможные месяц/день в начале, как в `iin.ts`. Это проверка формы записи, а не подтверждение личности или проверка по реестру.

## Вход

Для входа запросить код с `purpose: "login"`, затем вызвать `POST /auth/otp/verify` с `challengeId` и `code`.
Регистрация возвращает 201, вход — 200. Оба возвращают:

```text
{
  token, tokenType: "Bearer", expiresAt, idleExpiresAt,
  user: { id, iin, firstName, lastName, middleName?, phone, email?, roles, status, version, createdAt },
  session: { role, name, expiresAt, idleExpiresAt }
}
```

`iin` возвращается маской вида `900101••••23`. Полное значение остаётся в базе; оно не входит в ответы регистрации, входа и профиля.
`status`: `active` или `blocked`. Новые пользователи получают только `roles: ["resident"]`. Назначение других ролей и организация сотрудника относятся к следующему этапу.
`session.name` — фамилия и имя; `role` берётся из серверного профиля. Поля `blocked` и `patronymic` не возвращаются.

## Профиль и выход

Защищённые методы требуют `Authorization: Bearer <token>`:

- `GET /me` — свой профиль.
- `PATCH /me` — `version` и хотя бы одно поле из `firstName`, `lastName`, `middleName`, `email`.
- `POST /auth/logout` — выход из текущей сессии, ответ 204.
- `POST /auth/logout-all` — выход из всех своих сессий, ответ 204.

Изменение профиля увеличивает `version`. Несовпадение версии даёт 409 `stale`. Изменение и запись `AuditEntry` выполняются одной транзакцией.
В журнале сохраняются только изменяемые поля, без токенов, кодов и ИИН. Пустая строка или `null` очищает необязательное поле.
Телефон, ИИН, роли, статус и идентификатор пользователя через `PATCH /me` менять нельзя.
Авторизованные запросы обновляют `lastSeenAt`; обращения к публичному каталогу не продлевают сессию. Просроченная сессия не возобновляется.

Старые `/auth/codes`, `/auth/login`, `/auth/me` удалены: фронт к ним ещё не подключался.

## Ошибки

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте заполненные поля.",
    "fields": { "firstName": "required" }
  }
}
```

`message` — запасной текст. Интерфейс выбирает перевод по `code` и кодам полей.

| HTTP | Код                                                                        |
| ---- | -------------------------------------------------------------------------- |
| 400  | `validation_error`                                                         |
| 401  | `otp_invalid_or_expired`, `session_required`, `session_invalid_or_expired` |
| 409  | `registration_conflict`, `stale`                                           |
| 429  | `otp_rate_limited`                                                         |

Коды полей: `required`, `format`, `long`; `taken` оставлен в общем словаре фронта. Конфликт регистрации возвращается общим кодом без раскрытия чужого телефона или ИИН.
Лишние и запрещённые поля возвращаются как `format`. Пустое изменение профиля возвращает `validation_error` без выдуманных имён полей.
Существующие ошибки доставки и каталога также обёрнуты в `error`: `otp_delivery_failed` (503), `database_unavailable` (503), `service_not_found` (404).
Неизвестные пути, ошибки JSON и неожиданные ошибки сервера получают безопасный ответ без трассировки, SQL, содержимого запроса и внутренних имён.

## Границы этапа

Настоящие SMS, государственная идентификация, ЭЦП, роли сотрудников и подключение пользовательских экранов не входят в эту доработку.
Каталог пока сохраняет прежние идентификаторы и маршрут по slug; его согласование с новым фронтом выполняется отдельным этапом.
