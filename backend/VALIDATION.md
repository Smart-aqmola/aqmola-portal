# Проверка API и прав доступа

Дата последней проверки: 26 октября 2026 года.

## 26 октября 2026: ошибка EPERM при сборке устранена

Полная `pnpm check` завершилась с кодом 0: форматирование, ESLint, типы, четыре теста обработки временных ошибок, все 438 тестов фронта и сборка 366 страниц Turbopack прошли. Команда запускалась без временных переменных окружения. Проверки бэкенда этой доработкой не затрагивались; интерфейс не менялся, e2e не запускался.

Диагностика воспроизвела временный EPERM при mkdir внутри `.next`: три операции прошли при повторе через 100 мс. Добавлены ограниченные повторы только этих операций на Windows. Подробности и границы — [windows-build.md](../docs/windows-build.md). Права ОС, файлы зависимостей и версии пакетов не менялись. Предупреждение pnpm о режиме локального хранилища остаётся видимым, автоматическая переустановка зависимостей перед командами заменена предупреждением.

Next.js вывел отдельное предупреждение о безопасности установленной версии; финальная проверка продолжилась штатным механизмом Next.js после ранее показанного уведомления. Эта проверка не отключалась, обновление зависимостей не выполнялось.

## Дополнение: объекты недвижимости

Скомпилирован бэкенд, применена миграция `202610230003_properties`, Prisma validate прошёл; сравнение схемы с локальной базой не обнаружило расхождений. Все 31 тест бэкенда прошли, включая шесть новых сценариев объектов: доступ к своим данным, защита владельца и статуса, проверки формы, журнал, конфликт одновременных изменений и лимит одновременных добавлений. Новые тесты используют отдельную временную базу. API перезапущен; маршруты объектов проверены в живом Swagger.

Повторный `pnpm check`: форматирование, ESLint и типы прошли. В тестах фронта прошли 409 тестов, четыре рабочих процесса остановились с `EPERM` при чтении файлов jsdom. Отдельная повторная проверка трёх затронутых файлов прошла (26 тестов). Запуск всех тестов с одним процессом остановлен после отсутствия прогресса.

Отдельная сборка с Webpack и одним процессом сгенерировала все 366 страниц, завершила типизацию и сбор трассировок без `EPERM`; затем процесс завершился с кодом 1 и `SecurityFatalError` с рекомендацией обновить Next.js. Причина предупреждения отдельно не проверялась, зависимости не обновлялись. Полный `pnpm check` не считается пройденным.

Подтверждение прав на недвижимость и подключение интерфейса не реализованы; объекты остаются `unverified`.

Успешно выполнены:

- Генерация Prisma Client, компиляция TypeScript бэкенда, проверка схемы и статуса миграций.
- 25 тестов бэкенда: регистрация, вход, отзыв сессий, ограничения кодов, таймаут бездействия, согласование телефона, маска ИИН, изменение профиля с версией и журналом, формат ошибок и защита от раскрытия внутренних данных; все 12 ролей, разделение двух организаций, блокировки, назначение прав, первая выдача административной роли и одновременное снятие прав у администраторов.
- Проверка форматирования, ESLint, проверка типов фронта и 438 его тестов.

Полный `pnpm check` запускался, но не завершился успешно: финальная генерация страниц Next.js прерывается на Windows с `EPERM: operation not permitted, mkdir` в служебной папке `.next`.
Ошибка ранее воспроизвелась с Webpack и после ограничения параллельной генерации. Экспериментальная настройка параллельности удалена как не устранившая ошибку. На этапе ролей `pnpm check` повторно дошёл до сборки и остановился с тем же `EPERM` в `.next/types/app/[lang]/about`; остальные стадии прошли.
Проверка pnpm запускалась с `pnpm_config_verify_deps_before_run=warn`, чтобы установленный pnpm не переустанавливал зависимости автоматически из-за локальной настройки хранилища. Версии пакетов и lock-файлы не менялись.
В Prettier включён `endOfLine: auto`, чтобы проверять файлы с переносами Windows без массовой перезаписи исходников.

Интерфейс и `src/features/*/domain` не изменялись; `pnpm test:e2e` в этой доработке не запускался.
Для полной приёмки остаётся повторить успешный `pnpm check` в окружении без ошибки доступа к служебным папкам сборки.
