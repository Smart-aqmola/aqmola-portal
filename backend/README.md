# Локальный бэкенд Aqmola

Реализованы отдельный сервер NestJS, PostgreSQL, публичный API каталога и локальная регистрация и вход по одноразовому коду.
Фронтенд остаётся в корне репозитория и пока использует свои тестовые данные.
Заявки, недвижимость, документы, платежи и роли сотрудников будут добавляться следующими этапами.

## Требования

Node.js 24, pnpm 11. PostgreSQL 17 можно запустить через Docker либо локальный вспомогательный пакет.
Все команды ниже выполняются из `backend/`.

```powershell
pnpm install --frozen-lockfile
pnpm setup:env
pnpm generate
```

`.env` содержит только локальные настройки и не попадает в Git. Пример пароля предназначен исключительно для локальной разработки.

## База данных

Вариант без Docker:

```powershell
pnpm db:local
```

Команда запускает настоящую PostgreSQL 17 на `127.0.0.1:5433` и сохраняет данные в `backend/.postgres/`.
Для остановки используйте Ctrl+C. Повторный запуск сохраняет базу.
Пакет `embedded-postgres` используется только как инструмент локальной разработки и не нужен серверу в промышленной среде.

Альтернатива с Docker:

```powershell
docker compose up -d database
```

Не запускайте оба варианта одновременно: они используют один порт.

В другом терминале:

```powershell
pnpm db:migrate
pnpm db:seed
pnpm build
pnpm start
```

Загрузка начальных данных повторяемая и выполняется транзакцией: 20 территорий, 12 организаций, 10 категорий, 8 жизненных ситуаций и 43 услуги.
Источник — существующие вымышленные данные фронтенда. Это не импорт реальных данных поставщиков.
Новые изменения базы оформляются отдельными миграциями Prisma; применённые миграции не редактируются.

## API

Сервер: `http://127.0.0.1:3001`.
Swagger: `http://127.0.0.1:3001/api/docs`.
OpenAPI JSON: `http://127.0.0.1:3001/api/docs-json`.

| Метод | Адрес                                         | Назначение                  |
| ----- | --------------------------------------------- | --------------------------- |
| GET   | `/api/v1/health/live`                         | Проверка работы сервера     |
| GET   | `/api/v1/health/ready`                        | Проверка соединения с базой |
| GET   | `/api/v1/territories`                         | Территории                  |
| GET   | `/api/v1/categories`                          | Категории услуг             |
| GET   | `/api/v1/situations`                          | Жизненные ситуации          |
| GET   | `/api/v1/organizations?territoryId=kokshetau` | Организации по территории   |
| GET   | `/api/v1/services`                            | Поиск и фильтрация услуг    |
| GET   | `/api/v1/services/{slug}`                     | Карточка услуги             |

Параметры каталога: `q`, `territoryId`, `organizationId`, `categoryId`, `situationId`, `audience=resident|business`, `popular=true|false`, `sort=popular`, `page`, `pageSize`.
Размер страницы от 1 до 100, по умолчанию 12. Номер страницы от 1, по умолчанию 1.
`popular=false` не ограничивает список популярными услугами.
Поиск охватывает код, названия, описания и наименования организаций на всех трёх языках, без учёта регистра и различия е/ё.
Порядок результатов стабилен по коду; при `sort=popular` популярные услуги идут первыми.
В отличие от текущего фронтового поиска, ранжирования по совпадению в заголовке пока нет.

Ответ списка: `{ items, total, page, pageSize, pageCount }`.
Названия и описания возвращаются объектами `{ ru, kk, en }`, совместимыми с типами фронтенда; дата услуги — `YYYY-MM-DD`.
Параметр `lang=ru|kk|en` принимается для будущего подключения интерфейса, но пока не влияет на выдачу.
Неверные или неизвестные параметры возвращают HTTP 400, отсутствующая услуга — 404, недоступная база при проверке готовности — 503.

Отбор по территории не подтверждает обслуживание конкретного дома: проверка адреса и прав на недвижимость относится к следующему этапу.
Публичных методов изменения каталога пока нет. До добавления операций сотрудников необходимо реализовать ролевую модель и проверку полномочий.

## Регистрация и вход

Актуальные поля, маршруты, формат ошибок и согласованные решения: [CONTRACT.md](CONTRACT.md).

Локальная доставка кода работает при `NODE_ENV=development`, `SMS_TRANSPORT=local` и локальном адресе сервера.
`pnpm setup:env` создаёт `.env`, если его ещё нет, и генерирует случайный `AUTH_OTP_SECRET`, не выводя секрет в консоль.
Существующие настройки сохраняются. Ключ должен быть одинаковым у экземпляров сервера и сохраняться между перезапусками.
При отсутствии ключа или выборе промышленного режима сервер останавливает запуск: настоящего SMS-провайдера пока нет.

| Метод | Адрес                      | Назначение                               |
| ----- | -------------------------- | ---------------------------------------- |
| POST  | `/api/v1/auth/otp/request` | Запросить код для `register` или `login` |
| POST  | `/api/v1/auth/register`    | Подтвердить код и создать пользователя   |
| POST  | `/api/v1/auth/otp/verify`  | Войти по коду                            |
| GET   | `/api/v1/me`               | Получить свой профиль                    |
| POST  | `/api/v1/auth/logout`      | Завершить текущую сессию                 |
| POST  | `/api/v1/auth/logout-all`  | Завершить все свои сессии                |

Порядок проверки в Swagger:

1. Выполнить `auth/otp/request` с полями `phone` (мобильный номер в формате `+7…`) и `purpose: "register"`.
2. В ответе найти `challengeId`. Прочитать код из `backend/.local-sms/<challengeId>.json` на компьютере разработчика.
3. Выполнить `auth/register`: передать `challengeId`, `code`, `iin` (12 цифр), `firstName`, `lastName` и `consent: true`. `middleName` и `email` необязательны.
4. Полученный `token` вставить в Swagger через **Authorize**. Метод `me` вернёт профиль.
5. Для следующего входа запросить новый код с `purpose: "login"`, затем выполнить `auth/otp/verify`.
6. После `auth/logout` текущий токен перестаёт работать; `auth/logout-all` отзывает все сессии пользователя.

Код не возвращается в API и не пишется в журналы. Локальные файлы доставки не доступны через HTTP и исключены из Git.
Они предназначены только для вымышленных данных разработчика. Настоящая отправка SMS потребует отдельного адаптера.

Ограничения: код действует 5 минут, допускает 5 попыток и принимается один раз. Новый код отменяет предыдущий для того же номера.
Отправка разрешена не чаще раза в минуту, до 5 раз на номер в час и до 20 раз с одного IP в час.
Проверки защищены блокировками PostgreSQL, включая одновременное использование одного кода.
IP берётся из соединения, заголовок `X-Forwarded-For` не считается доверенным. При развёртывании за прокси потребуется согласовать доверенный прокси и ограничения для общих адресов.

Сессия действует до 7 дней, но завершается после 30 минут бездействия (параметр SESSION_IDLE_MINUTES). Клиент передаёт `Authorization: Bearer <token>`. В базе хранятся SHA-256 хэши случайных токенов и HMAC хэши кодов.
Токен выдаётся только при успешном входе или регистрации; в профиль и журналы он не включается. Сохранять его в `localStorage` при подключении фронта не следует; для браузера нужно согласовать HttpOnly-cookie или хранение в памяти.
Номер и ИИН уникальны. ИИН и ФИО пока являются заявленными пользователем данными: проверки по государственным реестрам, ЭЦП и подтверждения личности не реализованы.
Ошибки: 400 — неверные поля, 401 — неверный/истёкший код или сессия, 409 — конфликт регистрации, 429 — ограничение отправки, 503 — ошибка доставки.
Ответы авторизации помечены `Cache-Control: no-store`.

## Проверки

При работающей локальной базе и загруженных тестовых данных:

```powershell
pnpm build
pnpm test
```

Тесты поднимают отдельный экземпляр API на свободном локальном порту и проверяют реальные запросы к PostgreSQL: справочники, фильтры, страницы, карточки услуг, невалидные параметры, HTTP 404 и OpenAPI.

## Структура

- `src/` — сервер, параметры запросов и чтение каталога из PostgreSQL.
- `prisma/schema.prisma` — модель базы.
- `prisma/migrations/` — история миграций.
- `prisma/seed.ts` — загрузка вымышленных данных.
- `scripts/local-db.mjs` — локальная PostgreSQL без системной установки.
- `test/` — интеграционные тесты API.

Разрешённый источник запросов фронтенда задаётся через `WEB_ORIGIN`. По умолчанию это `http://127.0.0.1:3000`.
Следующий шаг по списку — роли и права доступа. Подключение фронта будем выполнять постепенно через существующий слой репозиториев.
