# Локальный бэкенд Aqmola

Первый этап: отдельный сервер NestJS, PostgreSQL и публичный API каталога.
Фронтенд остаётся в корне репозитория и пока использует свои тестовые данные.
Авторизация, заявки, недвижимость, документы и платежи будут добавляться следующими этапами.

## Требования

Node.js 24, pnpm 11. PostgreSQL 17 можно запустить через Docker либо локальный вспомогательный пакет.
Все команды ниже выполняются из `backend/`.

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
pnpm generate
```

`.env` содержит только локальные настройки и не попадает в Git. Пример пароля предназначен исключительно для локальной разработки.

## База данных

Вариант без Docker:

```powershell
pnpm db:local
```

Команда запускает настоящую PostgreSQL 17 на `127.0.0.1:5433` и сохраняет данные в `backend/.postgres/`.
Для остановки используйте Ctrl+C. Повторный запуск сохраняет базу.
Пакет `embedded-postgres` используется только как инструмент локальной разработки и не нужен серверу в промышленной среде.

Альтернатива с Docker:

```powershell
docker compose up -d database
```

Не запускайте оба варианта одновременно: они используют один порт.

В другом терминале:

```powershell
pnpm db:migrate
pnpm db:seed
pnpm build
pnpm start
```

Загрузка начальных данных повторяемая и выполняется транзакцией: 20 территорий, 12 организаций, 10 категорий, 8 жизненных ситуаций и 43 услуги.
Источник — существующие вымышленные данные фронтенда. Это не импорт реальных данных поставщиков.
Новые изменения базы оформляются отдельными миграциями Prisma; применённые миграции не редактируются.

## API

Сервер: `http://127.0.0.1:3001`.
Swagger: `http://127.0.0.1:3001/api/docs`.
OpenAPI JSON: `http://127.0.0.1:3001/api/docs-json`.

| Метод | Адрес                                         | Назначение                  |
| ----- | --------------------------------------------- | --------------------------- |
| GET   | `/api/v1/health/live`                         | Проверка работы сервера     |
| GET   | `/api/v1/health/ready`                        | Проверка соединения с базой |
| GET   | `/api/v1/territories`                         | Территории                  |
| GET   | `/api/v1/categories`                          | Категории услуг             |
| GET   | `/api/v1/situations`                          | Жизненные ситуации          |
| GET   | `/api/v1/organizations?territoryId=kokshetau` | Организации по территории   |
| GET   | `/api/v1/services`                            | Поиск и фильтрация услуг    |
| GET   | `/api/v1/services/{slug}`                     | Карточка услуги             |

Параметры каталога: `q`, `territoryId`, `organizationId`, `categoryId`, `situationId`, `audience=resident|business`, `popular=true|false`, `sort=popular`, `page`, `pageSize`.
Размер страницы от 1 до 100, по умолчанию 12. Номер страницы от 1, по умолчанию 1.
`popular=false` не ограничивает список популярными услугами.
Поиск охватывает код, названия, описания и наименования организаций на всех трёх языках, без учёта регистра и различия е/ё.
Порядок результатов стабилен по коду; при `sort=popular` популярные услуги идут первыми.
В отличие от текущего фронтового поиска, ранжирования по совпадению в заголовке пока нет.

Ответ списка: `{ items, total, page, pageSize, pageCount }`.
Названия и описания возвращаются объектами `{ ru, kk, en }`, совместимыми с типами фронтенда; дата услуги — `YYYY-MM-DD`.
Параметр `lang=ru|kk|en` принимается для будущего подключения интерфейса, но пока не влияет на выдачу.
Неверные или неизвестные параметры возвращают HTTP 400, отсутствующая услуга — 404, недоступная база при проверке готовности — 503.

Отбор по территории не подтверждает обслуживание конкретного дома: проверка адреса и прав на недвижимость относится к следующему этапу.
Записывающих публичных методов пока нет. До добавления таких методов необходимо реализовать авторизацию и серверную проверку полномочий.

## Проверки

При работающей локальной базе и загруженных тестовых данных:

```powershell
pnpm build
pnpm test
```

Тесты поднимают отдельный экземпляр API на свободном локальном порту и проверяют реальные запросы к PostgreSQL: справочники, фильтры, страницы, карточки услуг, невалидные параметры, HTTP 404 и OpenAPI.

## Структура

- `src/` — сервер, параметры запросов и чтение каталога из PostgreSQL.
- `prisma/schema.prisma` — модель базы.
- `prisma/migrations/` — история миграций.
- `prisma/seed.ts` — загрузка вымышленных данных.
- `scripts/local-db.mjs` — локальная PostgreSQL без системной установки.
- `test/` — интеграционные тесты API.

Разрешённый источник запросов фронтенда задаётся через `WEB_ORIGIN`. По умолчанию это `http://127.0.0.1:3000`.
Следующий шаг по списку — регистрация и вход. Подключение фронта будем выполнять постепенно через существующий слой репозиториев.
