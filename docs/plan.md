# План: тестовый фронт портала Aqmola

Статус: план подтверждён 2026-10-20. Этапы 1–3 выполнены; план уточнён по исследованию astana.kz ([docs/research/astana-kz.md](research/astana-kz.md)). Основа дизайна — `design/variants/1-panorama.html`.

Решения после исследования (2026-10-20):

- Афишу мероприятий в первую версию **не берём**.
- Опросы и 3D-туры — **после первой версии** (раздел «Позже» внизу).
- Тёмная тема и режим для слабовидящих — в **этап 10**.
- Услуги для жителей и бизнеса **разделяем переключателем** «Жителям / Бизнесу» (параметр адреса `for=resident|business`, по умолчанию «Жителям»).

## Цель первой версии

Рабочий фронт на тестовых данных: все пользовательские сценарии портала для жителей, бизнеса и операторов, три языка, телефон и десктоп. Без сервера и базы: данные отдаёт слой-заглушка, который позже заменяется на API без переписывания страниц.

## Стек

| Что               | Выбор                                                                            | Почему                                              |
| ----------------- | -------------------------------------------------------------------------------- | --------------------------------------------------- |
| Фреймворк         | Next.js (App Router), TypeScript strict                                          | Как в aqmola; страницы, роутинг и сборка из коробки |
| Пакетный менеджер | pnpm 10.28 (уже установлен)                                                      | Как в aqmola                                        |
| Стили             | CSS Modules + CSS-переменные (токены)                                            | Макет уже на чистом CSS, без лишней зависимости     |
| Шрифт             | Onest через `next/font` (вместо Jost: в Jost нет казахских букв)                 | Без внешних запросов к Google при работе            |
| Иконки            | Свои SVG-компоненты из макета                                                    | Без библиотеки иконок                               |
| Языки             | Словари ru/kk/en + сегмент `[lang]` в адресе по гайду Next.js                    | Без пакета; адреса вида `/ru/services`              |
| Состояние         | Состояние React + параметры адреса (фильтры, поиск)                              | Отдельная библиотека не нужна                       |
| Демозаявки        | `localStorage` браузера через слой данных                                        | Без сервера; позже — API                            |
| Тесты             | Vitest + Testing Library (логика и компоненты), Playwright (сценарии в браузере) | Стандарт для Next.js                                |
| Качество          | ESLint, Prettier, `tsc --noEmit`                                                 |                                                     |
| CI                | GitHub Actions: install, format check, lint, typecheck, test, build              | По глобальным правилам                              |

Node: 24 (обновлено 2026-10-20; Vitest 5 и jsdom 30 требуют 22.12+).

## Структура

```
src/
  app/[lang]/                 # страницы
    page.tsx                  # главная (Панорама)
    services/                 # каталог, фильтры, поиск
    services/[slug]/          # карточка услуги
    services/[slug]/apply/    # демозаявка
    situations/[slug]/        # жизненная ситуация
    applications/             # мои заявки
    applications/[id]/        # заявка, статус, история
    operator/                 # кабинет оператора (демо)
    news/, news/[slug]/       # новости
    tourism/, tourism/[slug]/ # места
    about/                    # о регионе и о проекте
  features/
    catalog/                  # услуги, ситуации, организации, территории
    applications/             # заявки, статусы, история
    content/                  # новости, места, «скоро»
    each: domain/ (типы, правила) · data/ (репозиторий: интерфейс + заглушка) · ui/ (компоненты)
  shared/
    ui/                       # шапка, подвал, кнопки, карточки, иконки
    i18n/                     # словари ru.json, kk.json, en.json, выбор языка
    styles/                   # токены, базовые стили
tests/e2e/                    # Playwright
```

Правило зависимостей: `ui` → `domain` ← `data`. Страницы получают данные только через репозитории.

## Этапы

1. ✅ **Каркас.** Next.js, git, ESLint/Prettier, Vitest, Playwright, CI.
2. ✅ **Дизайн-система.** Токены, шрифт Onest, иконки, шапка с мобильным меню и переключателем языка, подвал, плашка теста, кнопки, карточки, три языка и редирект по языку браузера. Живая страница токенов и компонентов: `/ru/design`.
3. ✅ **Данные-заглушки** (уточнены по исследованию astana.kz). 3 города + 17 районов, 12 вымышленных организаций, 8 жизненных ситуаций, **10 категорий**, 43 услуги, 6 новостей, 6 мест, 4 анонса «Скоро». У услуги: короткий **код**, категория, «популярная», «новая», канал (онлайн / нужен визит), срок в рабочих днях, длинное официальное название (для части услуг), дата изменения. Репозитории: поиск (по названию, описанию, организации и коду), фильтры (ситуация, категория, организация, территория, аудитория, популярные), пагинация, счётчики по ситуациям и категориям.
4. ✅ **Главная.** (Готово: «Мои заявки» пока приглашение войти и статусы, без вымышленного списка; блок контактов не делали, оставили демо-форму вопросов без телефона и e-mail; фото занимает верхнюю полосу hero.) Перенос «Панорамы» на компоненты. Поиск по названию или коду + выбор территории + переключатель «Жителям / Бизнесу» ведут в каталог с этими фильтрами. Ряд жизненных ситуаций, популярные услуги, «Мои заявки» (демо), новости, места, компактный блок «Скоро», контакты и демо-форма «Остались вопросы?» (без отправки, с пометкой).
5. ✅ **Каталог и услуга.** (Готово. Отдельной страницы ситуации нет: `/situations/<id>` ведёт в каталог с этим фильтром. Шаги и документы услуг генерируются по правилам из типа услуги и канала, это тестовые данные.) Отдельная страница `/services`: поиск, выпадающие фильтры «Организация» и «Категория», ряд категорий-иконок со счётчиками, переключатель «Жителям / Бизнесу», пагинация. Избранное (звёздочка, `localStorage`). Карточка услуги: описание, **инструкция по шагам**, список документов, срок в рабочих днях, канал, исполнитель, получатели, длинное название, дата изменения; кнопки «Заказать услугу» и «В избранное». Страница жизненной ситуации с категориями слева.
6. ✅ **Демозаявка и «Мои заявки».** Явный вход «как деможитель» / «как демопредприятие» (имитация входа; ЭЦП, SMS и eGov не подключаем), шаги заявки как в инструкции услуги (данные → объект → документы → проверка → подписание), номер DEMO, статусы, история. Тесты правил статусов. (Готово. Вход и заявки хранятся в браузере: `aqmola:session`, `aqmola:applications`; оператор в этапе 7 читает тот же список. Шаги мастера: объект → документы → проверка → подписание. Номер вида DEMO-2026-00001.)
7. ✅ **Кабинет оператора.** Вход «как демооператор» организации, список заявок своей организации, смена статуса (Подана → В работе → Исполнена / Отклонена). (Готово. Оператор выбирает тестовую организацию при входе; кабинет `/operator` с фильтром по статусам, страница заявки со сменой статуса и комментарием. Тестовые заявки добавляются кнопкой, потому что общего сервера нет.)
8. ✅ **Новости, туризм, о регионе.** Новости с темами, поиском и вкладками «Последние / Популярные»; туризм вместо 3D-туров: места с фото и указанием авторов. (Готово. `/news` — поиск, темы, вкладки «Последние / Популярные», страницы по 4; `/news/<slug>`; `/tourism` и `/tourism/<slug>` со ссылкой на услуги района; `/about`; `/situations` ведёт в каталог.)
9. ✅ **Языки.** Полные тексты услуг и новостей на kk/en. Казахский перевод черновой — нужна проверка носителем. (Готово. Переведены 43 услуги (название, описание, длинное название), 9 новостей, 6 мест, 4 анонса и подписи к фото. Тесты не дают оставить услугу, новость или место без kk/en. Казахский — черновик, нужна вычитка носителем.)
10. ✅ **Полировка.** Доступность (клавиатура, контраст, подписи), **тёмная тема и режим «крупный шрифт и высокий контраст»**, узкие экраны, e2e-сценарии, README с запуском. (Готово. Тёмная тема, высокий контраст и крупный шрифт (кнопка в шапке, хранится в браузере, без «мигания» при загрузке); тест контраста токенов; проверки структуры страниц (один h1, подписи, порядок заголовков); README. Не сделано: автоматический аудит axe (нужен пакет, ждёт согласия), проверка с экранным диктором вручную.)

## Риски и ограничения

- Казахский и английский тексты потребуют вычитки.
- Фото с Wikimedia (CC BY-SA) годятся для теста; для запуска нужны свои или лицензированные.
- Демозаявки в `localStorage` видны только в одном браузере; общая база появится с backend.
- Списки районов и организаций — тестовые, перед запуском сверить с официальными.
