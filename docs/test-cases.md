# Тест-кейсы (ТЗ 21.3)

Каждый сквозной сценарий из ТЗ 21.2 — один Playwright-тест в [tests/e2e/scenarios.spec.ts](../tests/e2e/scenarios.spec.ts). Он идёт на десктопе и на узком экране (375 px). Данные тестовые; вход оператора и администратора — демо-кнопки на `/ru/sign-in`, код из SMS — `123456`. Запуск: `pnpm test:e2e`.

## Сценарии

### С1. Заключение договора (ТЗ 21.2, 1)

| №   | Шаг                                                                           | Ожидаемый результат                                                   |
| --- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | Регистрация жителя, добавление объекта, подтверждение права через госсервис   | Объект «подтверждён»                                                  |
| 2   | `/contracts/new`, услуга «водоснабжение», поставщик подставлен                | Поставщик — Водоканал Акмолы                                          |
| 3   | Заявление, два документа, согласия, подпись (демо ЭЦП), отправка              | Номер `DEMO-DOG-ГГГГ-00001`                                           |
| 4   | Оператор поставщика: «на рассмотрении», затем «ожидает подписания заявителем» | Карточка в реестре оператора меняет статус, действия пишутся в журнал |
| 5   | Житель входит по телефону, открывает договор                                  | Статус «Ожидает подписания заявителем»; кнопка подписи                |
| 6   | Житель подписывает, оператор ставит подпись поставщика («заключён»)           | Статус «Договор заключён»                                             |
| 7   | Житель скачивает договор                                                      | Файл `dogovor.txt`                                                    |

### С2. Передача показаний (21.2, 2)

Объект и счётчик воды с первым показанием 120 → показание больше предыдущего, фото → номер `DEMO-POK-…` и статус «передано» → в истории видны значение, фото, статус. Ожидание: показание, меньшее предыдущего, не принимается с пояснением.

### С3. Пломбирование счётчика (21.2, 3)

Заявка «пломбирование / установка» на выбранную дату с актом → номер `DEMO-ZPR-…` → оператор: «в работе», «назначена дата», «выполнена» → заявка выполнена, счётчик получил данные пломбы.

### С4. Единая квитанция и оплата (21.2, 4)

Начисления по поставщикам → единая квитанция с итогом → оплата через демо-шлюз → статус платежа «оплачен», запись в истории платежей. Повторное уведомление шлюза не зачисляет платёж дважды (9.17); оператор вывоза мусора «молчит» (9.8).

### С5. Обработка обращения (21.2, 5)

Обращение с категорией и описанием → номер `ЭО-…` → оператор организации отвечает и закрывает → житель видит ответ в карточке и в уведомлениях.

## Не проверяется на фронте

Нагрузка, резервное копирование, настоящие интеграции (ЭЦП, шлюз, SMS) и серверные права — ТЗ 14, 15, 19–20, задачи бэкенда.
